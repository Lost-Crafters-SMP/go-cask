# Repository context

- This is a standalone content-addressable storage library module, `go.lostcrafters.com/cask`, not an application. The root package is `cask`; the public API and integrity contract are defined in `docs/design.md`. Tests cover ingestion, verification, confinement, native publication, process concurrency, and crashes.
- Keep library code at the module root; introduce subpackages only as needed (see `README.md`). `go.work` is ignored and is not part of the shared setup.
- V1 is a concrete filesystem store with SHA-256/SHA-512 keys. Keep ingestion single-pass, verify existing objects on duplicate publication, and preserve atomic no-clobber semantics. Native publication code is private and build-tagged; no backend interfaces or application policy belong here.

## Tooling and verification

- Use mise to resolve pinned tools rather than assuming global executables match. `mise.toml` defines tasks and versions; `mise.lock` is generated by `mise lock`, not hand-edited.
- Setup is `mise install` after the user has approved `mise trust`. If trust is blocked, ask the user to approve it; do not bypass it.
- Run `mise run fmt` before `mise run check`. Formatting uses golangci-lint's `gofmt` and `goimports`, with `go.lostcrafters.com/cask` grouped as local imports.
- `mise run check` runs build, formatting checks, lint, tests, and `go mod tidy -diff` without modifying source. Its dependencies have no enforced sequence; do not run it concurrently with formatting or dependency updates.
- Focused tests: `mise exec -- go test . -run '^TestName$' -count=1`; replace `.` with a package path for a subpackage. Task `test` always runs `./...`; use `mise exec` for Go flags rather than assuming task arguments are forwarded.
- After dependency changes, run `mise run tidy` before lint/check: golangci-lint uses `modules-download-mode: readonly`.
- Vulnerability scanning is `mise run vuln` (or `go tool govulncheck ./...`); govulncheck is pinned by the go.mod `tool` directive and needs network access for the vulnerability database. It is a CI quality gate, not part of `check`, to keep checks network-independent.
- `mise run test:race` requires a C compiler and is not included in `check`.

## Hooks and commits

- `mise run hooks:install` installs repository-local hk hooks with mise integration and requires a Git repository; do not assume hooks are already installed.
- Pre-commit formats staged Go files, then lints the whole module, preserving unstaged changes. Pre-push runs tests and the non-mutating tidy check; hooks do not replace `mise run check`.
- If upgrading hk, keep the tool pin in `mise.toml`, the schema URL and `min_hk_version` in `hk.pkl`, and the generated lockfile consistent.
- For commit messages and commit grouping, use `.agents/skills/conventional-commits/SKILL.md`; it does not authorize committing when only a message is requested.

## Go guidance

- Use current Go idioms and stdlib APIs; avoid deprecated/stale patterns such as `ioutil`, `interface{}` where `any` is appropriate, hand-rolled helpers already covered by `slices`/`maps`, and older replacements for `log/slog` or `math/rand/v2`.
- Prefer small consumer-owned interfaces and return concrete types. Do not introduce abstraction layers or dependency-injection frameworks without a clear need.
- Wrap errors with context using `%w` when callers may need `errors.Is` / `errors.As`; do not log and return the same error.
- Avoid naked returns and panics in library code except for truly unrecoverable programmer errors.
- Every goroutine must have a clear termination path; do not introduce goroutine leaks or unbounded channels/queues.
- Pass `context.Context` through operations that need cancellation or deadlines rather than accepting and then dropping it.
- Do not depend on map iteration order for deterministic output; sort explicitly where order matters.
- Prefer table-driven tests with `t.Run` when several cases exercise the same behavior.
